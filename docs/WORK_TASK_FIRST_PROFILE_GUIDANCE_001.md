## 确认存在的引导缺口

- `local-app/public/profile-file-import.js`只说选择旧导出或AI生成JSON，没有告诉用户首份文件从哪里来、没有JSON时做什么、文件放在哪里、导入后如何判断实际保存。
- `docs/PROFILE_UPDATE_AI_PROMPT.md`和现有空模板只在源码仓库，未列入`package-candidate.mjs`的包清单，也未通过本机静态资源提供。现有提示词仍说“交工程师处理”，与普通资料应在平台直接导入不一致。
- JSON里的`questions`目前只是“仍需本人核对的问题”文字列表，不能把它冒充已有的可操作岗位补答表单。必须区分导入待核对提示和已关联实际任务的补答。
- 侧栏固定显示“v0.2.0”，用户不能据此判断是否已安装支持导入的候选版本；包内已有`SOURCE.json`可作为真实版本依据。

## 限定实现范围

1. 在“资料与简历”现有入口就地补齐首次使用引导：有旧插件导出/已准备本人草稿时直接选择；只有简历、没有JSON时说明当前PDF候选提取边界，并提供可复制的资料整理提示词，让助手基于已有材料交付可下载JSON，而非让用户手写。不得内置或自动导入虚构示例作为本人资料。
2. 把必要帮助和提示词随程序包提供，并让页面内实际可用；更新提示词为“生成可在平台预览并本人确认保存的文件”，不再让普通补答每次找Engineer改代码/发包。说明JSON保存到本机“下载”等任意可选择位置即可，无须搬到程序目录；确认保存后平台自己持久保存，输入文件可作为备份。
3. 给出实际下一步与完成依据：预览本人字段→接受核实的变更→确认保存→检查真实字段和已接受项数。仅文件已选择、PDF附件已保存、或本轮接受0项都不能无条件显示“资料已完整就绪”；重复导入0项也不能误报失败。复用现有readiness、导入计数和版本，不建立第二套状态。
4. 同页说明后续正常岗位问题在平台“待处理”/对应任务中补答，并继续原任务。已导入JSON的未匹配问题、限定内容应明确标为待核对及可行下一步，不声称静态问题已进入可填写任务。不得为此新增模型API、通用聊天平台、OCR或站点适配。
5. 展示实际安装候选版本以核对入口能力，来源应为已有安装/包元数据，缺失时显示未知；不把profile版本当程序版本、不硬编码新候选号。
