## 实际产品流程

1. 队列进入原任务详情，核对后选择「确认检查原申请页」。沿同一任务在 APP 保存原题答案或明确留空。默认检查没有填写、上传或申请提交权限。
2. 在已核实的页面版本和完整答案就绪时，任务详情提供「授权填写并提交本次申请」。再次核对公司、岗位链接和编号、资料版本及申请邮箱、文件名、大小、附件 SHA-256、执行浏览器和本次动作。确认绑定当前表单、实际 tab/document、扩展和浏览器身份。资料、附件、答案、浏览器或页面变化时按当前检查和确认处理，旧检查、用途未核实及旧隔离许可均不能自动取得写入许可。已有提交边界的任务仅能核对结果。
3. 正常后台、扩展及产品授权链均使用真实任务 URL、租户、岗位和已核实的英文 renderer/schema 范围。地点读取本岗位的公开服务配置。继续使用页面原生控件、页面的预签配置和原生 S3 XHR 上传。文件名、大小、内容摘要、实际上传响应及精确对象引用与同一文档及请求绑定。
4. 进入提交阶段先落盘记录提交边界，再捕获和冻结完整申请正文，经最后授权放行页面原生 fetch。启用原生 Enterprise 验证时，保留页面本次产生的评估字段及原值，随全文冻结，不在证据中保存评估值。验证码缺失或额外验证字段不符时拒绝放行。回执关联同一请求摘要、原生响应、申请人、锁定附件及对应确认导航。新执行记录须有持久边界、最终授权及绑定文档的原生证据，才可入账为 `submitted`。
