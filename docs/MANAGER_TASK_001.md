## Engineer 唯一任务与完成标准

目标：在现有架构中完成一个 Greenhouse 招聘站从岗位识别到结果核验的执行路径，先交可验证实现和受控回放，再由 Manager 组织用户首次真实操作。沿用 Mattermost 已观察结构作为技术样本；该样本不是用户目标岗位，也不是投递授权。

1. **补缺而非重查**：只核实尚未展开的自定义选项、业务问题/辅助控件对应、附件分组标题及必填依据。优先已有原始证据；确需补采集时只读真实站，不填写、不选文件、不操作 CAPTCHA、不提交。记录实际来源与结构版本，无法观察的内容明确暂停，不猜通用 Yes/No 或附件可选性。
2. **接入现有任务链**：实现受限 Greenhouse 站点适配，覆盖发现/手动岗位链接、公司/租户/岗位身份核验、已确认资料匹配、原值和结构保护、附件身份/版本核对。不得只解除 local-v1 限制或将未核实站点标为通用支持。
3. **暂停与恢复**：缺答或人工验证时持久保存原题、选项、用途/来源、已确认内容、步骤、资料及附件版本；同任务同执行 profile 恢复前重查页面、身份及已有提交状态。答案记忆默认关闭，显式选择并支持查看、修改、撤销，严格限定范围；公司动机不跨公司套用。
4. **提交和结果**：发送前持久保存提交边界；仅可靠且对应本岗位/身份的回执记成功。断线、超时或结果不明只能核对，不重复提交；人工验证须交给用户。首次真实投递必须由用户确认岗位、资料、附件及提交动作。
5. **必要验证**：基于实际已观察结构，完成一个受控本地招聘表单的实际浏览器回放，覆盖填写/实际附件接收/缺答/同任务恢复/唯一提交/可靠回执，并对错误身份、原值或结构变化、版本变化、未知结果不重发做针对性验证。虚构数据仅发往本地 fixture；清楚区分合成回执验证与尚未观察的生产回执。沿用未变更历史证据，不跑无关完整套件、不制作新视频或大量截图。
6. **可用交付**：提交具体 SHA、改动范围、实际测试结果、未验证项、当前可用安装/启动入口与必要条件。Manager 据可用版本逐步带用户操作；未取得本人确认和真实结果前保持“真实提交未验收”。如当前生产表单、回执、权限或网络有硬阻碍，先完成独立实现/受控验证，报告一个精确下一动作，不把“仍待注册”当作真实适配已经完成。

优先顺序：唯一首站执行链和保护 → 可用交付及本人首次确认；普通小 Bug、换肤、重构、更多站点和额外演示后置。关键进展推送原分支并交 Manager 审核；未经 Manager 协调不并行调度会互相取消的 Actions。不要触碰真实用户资料、会话、凭据，也不要向企业试投虚构资料。
