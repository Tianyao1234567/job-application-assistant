## P2-A：页面已有选值与本地确认不同，保存后反复索答（P2）

固定源码的链路：

- `greenhouse-adapter.js` 的 `specialChoice/question` 将页面电话国家ISO读为 `selectedId`；真实inspect保持页面不变。
- [model.mjs:149](https://github.com/Tianyao1234567/job-application-assistant/blob/d649586b54d006ee86e4fbd5367c500bd482532f/local-app/model.mjs#L149)在 `q.selectedId !== own.selectionId` 时判已保存答案不可用，`answerBatch/finishGreenhouseInspection` 再次要求回答。
- 例如页面已有US，本人在APP明确保存CA；后台没有也不应改真实网页，下次同页检查仍US，因此再次索答。同一条件重复保存不能结束。此为源码可达路径，Manager没有冒称本机已执行此复现。
- 当前公开MV3选择us；它未覆盖页面既有选值与本人意图不同的恢复。现有模型负例从无选值变成us，仍应保留真正页面变化的保护，不能为了修复删除全部selectedId比较。

修复要求：区分**本人已保存的本地选择、确认时观察的网页基线、实际执行前当前网页值**。基线和原题未变时，同任务只读检查/重启应保留并复用本人意图，不因网页尚未被填写而无限索答。网页确实被人工或脚本改动、题目/选项变更时，继续保留原值与明确冲突处理；真正填写/发送前仍须核对实际值等于本人确认，不能把“本地已确认”冒充“网页已填写”。不得通过修改真实页来消除循环。

必要验证：实际APP在观察到页面US的基线下保存CA（共享+1），页面仍US；保存、独立重启与重新检查后同任务无需再答。再给一个基线之后发生真实选择变化的负例，证明不会静默覆盖或放宽执行核对。可用匹配当前真实控件的隔离页面构造基线；生产页面继续只读，不能为测试而替用户改企业表单。

## P2-B：结构化地点界面提供后端禁止的保存用途（P2）

- [profile-facts.js:12](https://github.com/Tianyao1234567/job-application-assistant/blob/d649586b54d006ee86e4fbd5367c500bd482532f/autofill-extension/shared/profile-facts.js#L12)仍把当前 `candidate-location / Location (City)` 映射到 `personal.location`；该动态控件候选不放在options，因此这个映射会成立。
- [app.js:538](https://github.com/Tianyao1234567/job-application-assistant/blob/d649586b54d006ee86e4fbd5367c500bd482532f/local-app/public/app.js#L538)据此提供“保存到个人资料”，资料地点为空时第540行默认选profile。
- [model.mjs:211](https://github.com/Tianyao1234567/job-application-assistant/blob/d649586b54d006ee86e4fbd5367c500bd482532f/local-app/model.mjs#L211)却要求所有controlKind只能save=task，导致整批保存拒绝。已有地点用户手动选择profile也会遇到相同冲突。现有公开MV3资料有地点且使用task默认，未覆盖这一情况。

本次最小决定：**动态结构化控件在此版本仍只保存到当前任务；界面提供的用途及默认值必须与后台一致。** 普通个人事实的保存/复用保持原行为，不为这次修复新增通用结构化资料系统，也不能删除后台用途保护。合法地点选择应一次随整批保存；真正失败时保留已输入草稿。

必要验证：个人资料地点为空，用真实APP搜索并选中候选，按默认界面一次保存整批成功；界面不提供后台必拒的profile/scope用途。原普通事实仍可存个人资料，非法动态用途经后台仍拒绝。不得仅在测试里强制切到task掩盖用户默认路径。
