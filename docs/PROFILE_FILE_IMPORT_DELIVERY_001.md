## 更新一次，之后导入资料文件

1. 在现有目录正常运行“停止.cmd”。保留完整目录、隐藏`.runtime`、依赖、已有浏览器及登录配置。
2. 把新版`update.cmd`放到实际“启动.cmd”旁运行；看到`UPDATE_COMPLETE`后，用原来的“启动.cmd”正常打开。不重新安装，不清空资料。
3. 在“资料与简历”的**选择资料文件**入口，选择电脑上已有的旧插件v3导出，或按固定协议生成的增量JSON。完整schemaVersion1 profile草稿也可作为变更提案选择。
4. 查看自动预填的变更预览、原值与原始依据。记录归属不明确时，选择已有记录ID或明确新建；有冲突的字段默认保留，只有明确替换才接受。完整资料仍有未保存编辑时，先保存或明确放弃，所选文件会保留。
5. 一次勾选核对声明并保存。未列出字段不动，null不删除原值；未匹配、未支持及限定语义保留在本机导入记录中。岗位答案只有与本机任务、原题和实际选项匹配后，才可选择送入原任务补答；不会执行申请。

以后请其他AI按[固定格式提示词](PROFILE_UPDATE_AI_PROMPT.md)整理真正的新补答，导入新JSON即可，无需每次修改源码或下载程序。尚未升级candidate.8的旧入口仍不能直接接收增量格式。

## 实现与数据保护

- 新的本机文件选择先解析JSON，再通过既有Origin、X-Local-Key及POST管理接口生成预览。500KB上限、严格白名单、版本/形状/路径限制；原型路径、命令字段和伪造confirmed拒绝。文件内容只当数据。
- 预览绑定当前profile版本及数据摘要，确认时再次核对。过期预览、变化的题目/选项或无效选择整批拒绝，不部分覆盖。保存仅一次原子写入；原PDF文件、摘要、简历版本、答案和已跨提交边界任务保留。
- 旧经历ID按类型及原ID生成独立稳定标识，不按同学校/公司名猜同一记录；用户明确的ID匹配会保留，重复文件不重复新增经历或提升资料版本。
- 每项资料提供旧值、来源、冲突及处理选择。新增字段需本人核对才confirmed；新导入不会静默替换已确认旧值。未指定语言为null时保留旧语言值，未列出的其他字段不动。
- 旧项目四类描述/职责段全部保留并整合description，不把长段职责当role。合并内容超过现有10000字限制时完整保留待处理，其他有效字段仍可保存。
- 无对应字段的信息保留在本机同一state的导入记录，关联原来源和待处理条目，没有另建脱离profile/答案系统的资料库。身份证件、密码、验证码、Cookie及凭据内容完全排除，仅显示无原值警示。
- 岗位答案须匹配实际等待补答的非unknown任务、岗位/站点/公司上下文、原题及当前有效选项。没有明确归属或匹配不唯一则待处理；文件声明的ID不构成执行权限。完整批次经本人选中后调用原saveAnswerBatch、仅保存本任务并等待本人继续；部分批次只预填当前问题的待核对草稿。资料更新后的再次岗位确认保留适用的已答原题，不需要重抄。
- 资料保存按既有规则撤回旧版本的待执行确认。没有新增提交授权、不创建任务、不点击企业提交，unknown始终只核对。重复导入不重新启动申请。
