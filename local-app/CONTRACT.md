# Local application implementation contract (v0.2.0)

Root: current repository checkout. All writes/caches/profiles/temp inside this root. No cloud. Node 24 built-in HTTP server. Dashboard origin http://127.0.0.1:17321; local recruiting fixture origin http://127.0.0.1:17322. Backend source `local-app/server.mjs`, `local-app/model.mjs`, fixture `local-app/fixture.mjs`. UI `local-app/public/`. Runtime `.runtime/`, tests `.runtime/tests/`, production browser `.runtime/browser/production/`; never remove production profile in tests.

## Authentication / bridge

Dashboard HTML server injects `<meta name="local-key" content="...">`. Dashboard fetch uses `X-Local-Key` for all /api calls. Mutation requests JSON (except resume upload described below). Server checks Host, Origin/Sec-Fetch-Site and key. No CORS for web origins. Extension paired by dashboard content script reading this meta and sending key to extension on explicit page `window.postMessage({channel:'job-local',type:'connect',key}, location.origin)`. Content script validates exact origin+port and top frame. SW accepts pairing only from this dashboard origin. SW opens runner/index.html and stores server key. Runner fetch includes X-Local-Key, extension origin accepted only on bridge routes. Runner never executes arbitrary page script/selector from server.

Runner POST /api/bridge/poll {clientId,profileId,extensionId}; returns {command:null|{id,op,site,task?,payload}}. Command has 60s lease. One active client lease. POST /api/bridge/result {clientId,commandId,result}; result error {ok:false,kind:'login'|'account'|'structure'|'manual'|'paused'|'failure',message}. Before EVERY page mutation runner POST /api/bridge/authorize {clientId,commandId}, returns {allowed:boolean}. No mutation on denied/network failure. Runner heartbeat POST /api/bridge/heartbeat {clientId,profileId,extensionId}. profileId is random installation id stored in chrome.storage.local. Backend scopes login state to profileId. Backend returns display-friendly state; does not log bodies/secrets.

## Extension commands / local fixture adapter

Site {id,name,adapter:'local-v1'|'unsupported',origin,listUrl,loginUrl,tenant,expectedAccount,mode:'demo'|'real',enabled}. Only local-v1 origin 17322 is supported. Fixed selectors in adapter. `task` subset {id,jobId,url,company,title,mode,tabId?}. Every result may include tabId,url (local exact origin). Backend records actual steps from results.

- discover: payload {}; open listUrl (visible), read DOM `[data-job-id]` anchors; result {ok:true,jobs:[{jobId,title,company,location,url,tenant}]}.
- check: open loginUrl or existing site page; read actual browser DOM `[data-session-status]` with data-account/data-tenant (fixture marker only); result {ok:true,login:{status:'ready'|'login'|'expired'|'verification'|'unknown'|'account',account,tenant},tabId,url}. Do not read cookies/passwords. No form mutations.
- open: payload {url}; open URL visible; result {ok:true,tabId,url}.
- inspect: open task.url (detail), then explicit `[data-apply-link]`, inspect application, existing receipt first. result {ok:true,tabId,url,receipt?:{id,jobId,account,fileName,fileSize,sha256},login:{...},question?:{key:'motivation',text,scope},layout}. Form selector `[data-application-form]`, hidden jobId, fixed fields. Missing question captured BEFORE fills. Backend may continue fill+upload before wait answer.
- fill: payload {entries:[{key,value,confirmed}],layout}; reuse original guard/scan/fill (inject files). Map explicit field name via local adapter, multi experience slots based on stable profile entry IDs. preserve original values, reject layout change. authorize before each apply/field. result {ok:true,layout,filled:number}; protected or conflicting values -> manual. No raw values in result.
- upload: payload {file:{name,mime,base64,size,sha256},layout}; actual DataTransfer/File assignment in target isolated world, input/change; authorize then compare files name/size. result {ok:true,fileName,fileSize,sha256,layout}.
- answer: payload {key:'motivation',text,answer,layout}; fixed exact question text+scope must match. authorize then set only ordinary question, protect credentials. result {ok:true,layout}.
- submit: payload {layout}; inspect existing receipt/login/form exact job+tenant+account+layout; authorize immediately before explicit `[data-submit-application]`. Form validation must pass. Click exactly once. Wait for `[data-receipt-id]` up to 5s. result {ok:true,receipt:{id,jobId,account,fileName,fileSize,sha256}} or {ok:false,kind:'unknown',message:'...'}; NEVER retry click, including after missing result.
- verify: read existing receipt using local fixture `/site/{tenant}/receipt/{jobId}` in actual visible tab (GET); result {ok:true,receipt:{...}|null,login:{...},tabId,url}; never submits. If not logged in return login and no receipt.

Fixture routes: GET /site/{tenant}/jobs, /site/{tenant}/jobs/{jobId}, /site/{tenant}/apply/{jobId}, /site/{tenant}/login, /site/{tenant}/receipt/{jobId}. Tenants alpha,beta. Login native form POST /site/{tenant}/login {account:demo}; default expectedAccount `demo`; alpha requires login, beta public session demo. Local test jobs alpha cpp-001 missing motivation, cpp-002 normal; beta web-001 normal; others filtered. Alpha login form only has account selector (demo/other) and submit, no credentials. Session cookie scoped per tenant. Receipt route has markers and selected file digest. Application uses browser form FormData POST receives actual multipart bytes. Support loss of visible receipt after accepted request with scenario controlled through test API, not fake submission counters. Persist receipts uniquely by tenant/jobId/account.

## Dashboard API (all return JSON)

GET /api/state -> {version,now,connection:{connected,lastSeen,profileId},running,paused,settings,sites,tasks,issues,profile:{version,data,mode},resume:{version,name,size,sha256}|null,nextRun,lastSchedule,readiness:string[],stats:{demo:{submitted,today},real:{submitted,today}}}.
Task {id,jobId,siteId,title,company,location,url,source,discoveredAt,filterReason,dedupeKey,mode,status,phase,steps:[{at,label,detail}],issue?,tabId?,currentUrl?,profileVersion,resumeVersion,result?,pauseReason?}. Status: queued,running,waiting_answer,waiting_user,paused,submitting,submitted,unknown,failed,skipped,cancelled. Issue {id,kind,siteId?,taskId?,title,detail,question?,createdAt,status:'open'|'resolved'|'skipped'}.

POST /api/action {action,...}: `demo` (seed enabled demo settings/profile/resume, never real), `run` (discover then queued work), `pause`, `resume` (all), `discover`, `add` {url}, `task-pause` {taskId}, `task-resume` {taskId}, `task-skip` {taskId}, `verify` {taskId}, `answer` {taskId,answer,save:boolean}, `site-check` {siteId}, `site-open` {siteId}, `site-skip` {siteId}, `site-resume` {siteId}, `browser-open` (opens dedicated production browser dashboard), `stop` (pause; shutdown handled scripts). Responses {ok:true,...} or {ok:false,error:Chinese message}. Do not offer arbitrary replay of unknown.
POST /api/settings {settings:{scheduleEnabled,time:'09:00',dailyLimit:3,keywords:[],cities:[],visual:true,mode:'demo'|'real'},sites:[...]} -> saves after validation (real unsupported). POST /api/profile {data:schemaVersion1,mode:'demo'|'real',confirmed:true} validates via original schema; version increment. For friendly editing UI can build full schema from editable personal + education/experience/projects; advanced JSON optional.
POST /api/resume {name,mime,base64,mode:'demo'|'real'} max 8MB, stores only directory-local file, hash/version. File picked via browser file picker; no arbitrary OS file path API. UI may show name/hash/version.

Dashboard content script emits `window.postMessage({channel:'job-local',type:'extension-ready'},location.origin)` on load and listens connect. UI Connect button posts above connect with meta key. Query `?autoconnect=1` can auto emit connect for one-click dedicated browser. UI should show absent extension with load instructions. All render uses textContent; no unsanitized innerHTML.

No fake progress. Poll state 1s. UI no external fonts/CDNs. Separate demo/real indicators. Missing real configuration visible, no example filters used in real mode.
